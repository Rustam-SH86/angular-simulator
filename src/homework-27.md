1) это Singleton и Будет создан один экземпляр CounterService.
Потому что:
a. providedIn: 'root' регистрирует сервис в корневом Injector приложения.
b. ComponentA впервые запрашивает CounterService. Injector создаёт экземпляр и сохраняет его.
c. ComponentB запрашивает тот же токен CounterService.
d. Корневой Injector находит уже созданный экземпляр и возвращает его повторно.

2) Будет создано два экземпляра CounterService. Потому что у каждого ChildComponent свой локальный инжектор и свой сервис через провайдеры: CounterService; корневой экземпляр здесь не создаётся.

3) ChildComponent получит локальный экземпляр LoggerService из инжектора родительского компонента, потому что Angular берёт ближайший провайдер у родителя, а до корневого не доходит.

4) Один экземпляр LoggerService. Сначала регистрируется сам LoggerService, а потом токен LOGGER через useExisting просто ссылаетсяется на уже существующий экземпляр, не создавая новый. Поэтому a и b указывают на один объект, и сравнение даст true.

5) Фабрика вызывается при первом inject LoggerService, потому что Angular создаёт зависимость лениво, после этого экземпляр кэшируется и повторно фабрика не вызывается.

6) в value будет массив ['A', 'B'], потому что значения для одного токена накапливаются по порядку, а не перезаписываются

7) Если провайдера нет, с optional: true в logger будет null, и ошибки не будет, потому что Angular просто возвращает null, если зависимость не найдена. Без optional была бы ошибка отсутствующего провайдера.

8) Будет ошибка, потому что с self: true Angular ищет LoggerService только в самом компоненте, а там провайдер не объявлен; до корневого он уже не поднимется.

9) ребёнок получает родительский локальный экземпляр, а не корневой.
В этом конкретном примере у ребёнка и так нет Provider, поэтому без skipSelf результат был бы таким же: обычный поиск проверил бы ребёнка, ничего не нашёл и поднялся к родителю. смысл skipSelf проявляется, когда у текущего компонента тоже есть локальный Provider, но нам намеренно нужен экземпляр уровнем выше.

10) Angular выбросит ошибку отсутствующего Provider для ApiService.

11) Один экземпляр: providedIn: root даёт один и тот же сервис, так что logger1 === logger2.

12) Два экземпляра: локальный в Header и корневой; Header берёт свой, а Dashboard и UserCard — корневой по цепочке до root. UserCard -> Dashboard -> AppComponent -> root; Header пропускается.

13) Цепочка: inject A запускает создание A, тот запрашивает B, дальше по цепочке создаются C, D и LoggerService, потом всё собирается обратно и кешируется.

14) сначала в памяти четыре объекта компонентов. После inject UserService появятся три объекта сервисов — UserService, ApiService, LoggerService, потому что они зависят друг от друга; итого будет семь объектов. 

15) 
ApiService — providedIn: 'root'
Нужен всему приложению для выполнения HTTP-запросов.

AuthService — providedIn: 'root'
Все части приложения должны использовать одного текущего пользователя.

CartService — providedIn: 'root'
Корзина должна сохраняться при переходах между страницами.

ProductFilterService — providers маршрутов
Для «Телефонов» и «Ноутбуков» нужны отдельные фильтры, которые уничтожаются после ухода со страницы.

NotificationService — providedIn: 'root'
Уведомление может показать любой компонент приложения.

ThemeService — providedIn: 'root'
Всё приложение должно использовать одну общую тему.

DashboardStatisticsService — providers маршрута Dashboard
Статистика нужна только на Dashboard и больше не нужна после ухода с него.

UserTableStateService — providers компонента Users
Состояние таблицы используется только страницей пользователей и её дочерними компонентами.

ModalService — providedIn: 'root'
Любой компонент должен иметь возможность открыть общее модальное окно.

LoggerService — useFactory
Фабрика выбирает реализацию: консоль в development или сервер в production.

AppConfig — InjectionToken + useValue
Это готовый объект настроек, а не класс сервиса.

CurrencyFormatter — InjectionToken + useValue
Формат числа является готовым конфигурационным значением.

AnalyticsService — условный Provider
Provider регистрируется только при включённой аналитике, поэтому выключенный сервис не создаётся.
